# 為什麼先前是 6.6，這次是 7.1？

兩個數字都是 **SHA3 前的原始八路資料**的 SP 800-90B 統計保留估計。

| 比較 | 舊版：健康熵源單獨部署 | 新版：健康熵源與 SHA3 同一份電路 |
|---|---:|---:|
| 初始原始資料估計 H_I | 7.192697 | 7.092671 |
| RO 重啟資料列向估計 H_r | 7.191294 | 7.129484 |
| RO 重啟資料欄向估計 H_c | 6.638383 | 7.258976 |
| 最後保留 min(H_I,H_r,H_c) | **6.638383** | **7.092671** |

單位都是 bits／八路樣本。每個時刻取八路 0/1，合成一個八位元樣本，所以理想上限為 8 bits。7.09 比 6.64 更接近上限，表示本次資料在工具採用的估計方法下，有較高的保守不可預測資訊估計；不是說能從八個實體位元中挑出七個「保證隨機」的位元。

最主要的數值原因是：舊版被 H_c=6.638383 拉低；新版的重啟估計比初始估計高，因此最後保留初始 7.092671。舊版初始估計其實比新版高，不能說所有指標都改善。

H_r 觀察每次 RO 啟動後的一列資料，H_c 把多次啟動後相同位置的樣本沿欄排列。後者是為了檢查每次重新啟動後是否容易出現位置固定的規律。舊版工具在欄向資料上給出較低估計；這次沒有被該項拉低。

## 與加入 SHA3 的關聯

新版本多了 SHA3、DMA 與連接電路，Vivado 重新安排元件位置和導線。即使 RO RTL 相同，實體延遲、振盪頻率與耦合可能改變；兩次實驗的環境條件也未做受控對照。因此統計結果不同是合理的，但不能將差異唯一歸因於 SHA3，也不能宣稱 SHA3 增加了物理熵。

本次量到的 7.092671 還沒有經過 SHA3。真正經過 SHA3 的資料是每批 1024 bytes 壓縮後的 32-byte 摘要。它的功能已逐批核對；其 SP 800-22 輸出初測另外收集與執行。

SHA3 是固定的確定性函數：相同輸入一定得到相同摘要。它的用途是混合、濃縮已有的不可預測資訊；如果原始輸入完全可預測，不能靠 SHA3 讓它憑空取得真正隨機性。

因此這三件事要分開：

1. **原始熵估計 7.092671 bits／八路樣本**：描述本次 raw 資料的估計。
2. **SHA3 輸出長度 256 bits**：描述每批輸出的長度，不是已保證的熵量。
3. **SP 800-22 的 P-values**：檢查輸出是否呈現特定統計異常，不是熵量分數，也不能直接和 6.6／7.1 比大小。

目前專題可以收尾為「已完成健康熵源與 SHA3 的 FPGA TRNG 應用原型，具原始熵評估、端到端功能驗收，另進行單條百萬 bits 的輸出統計初測」。不需要將本次應用收尾擴大成正式產品認證。
