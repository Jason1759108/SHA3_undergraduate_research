# 原始熵源階段的完成條件與後續範圍（2026-11-11）

這份文件固定本專題下一段的範圍，避免反覆加做沒有明確問題的短資料測試。它是研究原型的建議驗收計畫，不是 NIST 認證程序，也不是「任意電壓、溫度、板子都成功」的保證。

## 先區分兩個里程碑

**里程碑 A：目前版本的原始來源初步量測與資料評估。** 固定板號 21600、25 MHz、divider 512、現有 bitstream，記錄分批啟停方式、核對百萬點資料，再取得 non-IID 與 RO 重啟測試結果。結果見 `captures/board_21600/assessment_20261111/REVIEW.md`。這是本次工作的終點，不會因為想得到更漂亮的數字而繼續換設定收資料。

**里程碑 B：能作為 TRNG 輸入的受監測原始熵源原型。** 除里程碑 A，還需要來源與適用範圍說明、保守熵信用的依據、啟動/運行健康檢測，以及最後版本的驗收。以下三項是進入 SHA3 整合前的完成條件。

## 剩餘三項完成條件

### 1. 凍結來源、使用範圍與熵信用

- 記錄 RO 結構、同步器、暖機 1024 週期、樣本格式、取樣時脈、每批啟停及資料可用的時間點。
- 說明預期的熵來自實體時間抖動；固定振盪頻率與取樣相位本身不能當成不可預測性的證據。資料估計不能取代物理來源解釋。若無法合理支持來源模型，就必須補充量測或更換來源，不能只靠 SHA3 遮住問題。
- 本階段先限於這塊板的已測實驗條件。電壓/溫度未受控或未記錄的地方明確標示，不延伸成跨板、寬溫、抗攻擊的聲明。
- 為實際使用選擇有依據且保守的「每個八路樣本計入多少 bits 的熵」。工具輸出的 6.65 左右是本批資料估計，不直接當作保證。逐通道數字不可直接相加。不同版本/條件的結果採保守處理，不能只選最高的一次。
- 定義未來正常操作是否保持每 1024 點啟停。若改為長時間持續 RO、改時脈或改實體配置，需重新檢查資料是否代表新操作方式。

完成判據：來源、版本、範圍、重啟與可用狀態、熵信用及其理由都能寫清楚；不能把仍待確認的模型說成已證明。

### 2. 建立對應來源的健康監測與故障處理

- 現有「每路連續 128 個相同值」是基本卡死保護，現有暖機是等待電路穩定；兩者都不能直接稱為完整 SP 800-90B 啟動/運行健康檢測。
- 規劃 RCT（Repetition Count Test，重複次數檢測）與 APT（Adaptive Proportion Test，視窗內比例檢測），並依選定熵信用、樣本定義及允許誤報率決定門檻，而不是看這批資料最長連續值後隨意設門檻。
- 啟動檢測完成前不提供有效亂數。運行中故障時停止有效輸出、保留故障狀態；清除與恢復方式必須明確。
- 本機以正常樣本及故障注入驗證：固定值、偏置突增、門檻前一點/當點、視窗交界、reset、abort、watchdog、連續命令，以及健康檢測失敗後沒有資料被錯誤標為有效。
- 改 RTL 後對新版本做控制器、實際 BD 系統模擬、host 分支回歸，核對時脈/reset/地址、時序、DRC、RO 實體與發布檔。

完成判據：門檻有依據、邊界行為正確、故障路徑可驗證、沒有將不健康來源輸出交給下一級。

### 3. 最終候選版本上板驗收與獨立復測

建議規劃兩段明確的實板工作，不再繼續掃描更多 divider：

1. **新版本功能驗收**：發布檔與接線檢查、初始 RO 關閉、正常擷取、停止/恢復、健康檢測故障處置。故障注入應有明確的測試介面與離線驗證，不在共用板上任意短接、改電壓或連續重載未知電路。不能注入的故障保留模擬證據並註明限制。
2. **固定設定資料復測**：在最終候選版本上重新收同等規模的原始與重啟資料，離線重做評估；與目前基準比較。這是為了確認最終實作與量測可重現，不是反覆重跑直到通過。故障或顯著退化必須查原因。

這兩段可依實驗室時段安排在同一次預約中，分開初始化與記錄。原始擷取一千批已含一千次 RO 啟停，但不等於一千次整板上電。若研究聲明要涵蓋其他溫度、負載或板子，才另外規劃那些條件的量測。

完成判據：最終硬體版本通過既定功能與故障驗收，復測支持所選熵信用，差異得到解釋，所有資料可追溯。若修改後改變 RO 配置或操作方式，不能把舊 bitstream 的 PASS 當作新版本已通過。

這是「三項交付條件、其中兩段上板工作」的計畫，不是無論結果如何都只需固定幾次按鈕。若有失敗，修正後重驗受影響項目；不額外增加無關檢測。

## 里程碑 B 完成後，才開始的完整 TRNG 工作

1. 接入已驗證 SHA3，定義原始樣本打包、累積量、輸出長度與有效訊號。
2. 依熵信用和調理分析決定每次 SHA3 輸出前要累積多少資料。SHA3 不增加來源本來沒有的物理熵，256-bit digest 不自動等於 256 bits 的真實熵。
3. 驗證整合後的資料流、等待/背壓、重設及來源故障時停止輸出；再加入 SHA3 故障注入，評估錯誤修復機制的效果與限制。
4. 量測可用輸出速度、資源與功耗；統計品質與容錯結果分開報告。

這些是完整 TRNG 的整合驗收，不應全部混稱為「原始來源還沒測完」。PUF 專題由另一位組員負責；PUF 希望同一晶片有可重現特徵，TRNG 希望每次產生新的不可預測資訊，驗收目標不同。

## 標準依據

[NIST SP 800-90B 正式版](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/nist.sp.800-90b.pdf)：第 3.1 節為資料與熵評估；第 3.2 節包含來源說明、操作條件等要求；第 4 節為啟動/運行健康檢測。第 3.1.1 節對無法取得單段百萬點的情況允許串接每段至少 1000 點資料，但仍須正確說明來源操作。統計工具結果與完整標準符合性是不同層次。
