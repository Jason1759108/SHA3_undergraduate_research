# 來源、健康監測與門檻依據

## 來源與適用範圍

來源結構沿用八路 5/7/9/11/13/15/17/19 級奇數反相 RO，實體為 8 個 NAND LUT2、88 個反相 LUT1；輸出各經兩級同步器。預期不可預測性來自實體跳變時間的抖動，固定頻率、相位或模擬中的偽隨機序列都不能直接當成物理熵證據。

只主張研究用候選來源，先限定 PYNQ-Z2、xc7z020clg400-1、25 MHz、divider 512、目前驗證的硬體版本與實驗條件。沒有寬溫、跨板、電壓範圍或抗干擾保證。物理來源模型及熵信用仍待最終量測支持，不宣稱正式 SP800-90B 驗證完成。

第二階段同板資料估計：八路聯合約 6.65 bits/樣本，逐通道重啟後約 0.795..0.850 bits/位元樣本。這些是資料估計，不是物理保證，也不可相加來產生新的聯合下界。

本版增加了啟動取樣，也重新綜合/佈局；RO 實體位置可能改變。故第二階段的數字僅是選擇初步監測假設的參考，不能直接沿用成新 bitstream 的熵信用。

## 明確的監測假設

- 對每個通道的二元樣本，暫用 H_monitor=0.5 bits/sample。
- alpha=2^-20 是每個測試的名目誤報設計值，不是整張板一生的誤報機率，也不是已量到的錯誤率。
- H_monitor 低於目前逐通道資料估計，作為研究初始設定；它不是經來源模型證明的保守熵下界。若新版本資料不支持此假設，必須調查來源與設計，不能只調鬆門檻讓資料通過。
- **目前分配給 TRNG 的正式熵信用仍未設定。** 不使用 8x0.5 或 6.65 直接決定 SHA3 輸出量；那是後續來源/調理分析工作。

## RCT：重複次數檢測

依 SP800-90B 4.4.1，C=1+ceil(-log2(alpha)/H_monitor)=41。第一個樣本計為一次；第 40 個相同值還不觸發，第 41 個觸發。每路獨立記錄，RCT run 不因 APT 視窗或啟動/正式擷取交界而重設。

## APT：參考值比例檢測

依 4.4.2 的 reference-symbol 演算法，每路每個 1024 點視窗，以第一個值為參考值，計算它在該視窗出現的次數（包含第一點）。達 793 次即觸發；視窗只在完整 1024 點後重新選參考值。沒有把每個滑動視窗、總 1 比例或兩種值雙向檢測混稱為同一算法。

門檻依標準註腳的 binomial(W,p) 算式，W=1024、p=2^-0.5：

- Pr(B>=793) 約 7.39829e-7，低於 alpha。
- Pr(B>=792) 約 1.06051e-6，高於 alpha。

`sim/check_policy.py` 用 Python 標準函式庫在 log-domain 計算並核對，沒有依賴 SciPy。二項尾機率是該設計模型下的計算，不將它當作對相關實體資料的無條件誤報證明。

## 啟動、批次與故障行為

1. 每次 START 清本次監測狀態並啟用 RO。若上次有故障或 abort，必須先明確 CLEAR；START 不偷偷清故障。
2. 先等 1024 個 25 MHz 週期，約 40.96 微秒，讓振盪與同步器暖機。暖機不是健康檢測本身。
3. 用所選 divider 收集 1024 個啟動健康樣本，持續 RCT/APT。這些樣本不寫入對外 RAM。
4. 通過後收集 1024 個 payload 樣本，持續相同 RCT 狀態；APT 按視窗自然前進。
5. 直到整批完成、startup_ok=1、所有故障旗標為零，才令 batch_valid=1，允許 RAM 讀取。以前某個樣本暫時沒有觸發故障，不代表整批已能釋出。
6. 任一當前樣本失敗立即終止；失敗優先於最後一點完成。保留 RCT/APT 通道遮罩，RO 關閉，整批 RAM 不可讀。
7. abort、watchdog、reset 同樣不能留下有效批次。失效批次的 count 只供診斷，不代表有可用資料。

最長允許 divider=4096：2048 點加暖機約 0.3356 秒，低於 0.8 秒硬體 watchdog；驅動正常等待上限 2 秒。MMIO 本身不回應時，Python 的逾時無法保證解除，仍需管理員確認。沒有增加外部腳位、DMA 或新的 DDR 主動存取。

## 健康監測能證明什麼

它驗證是否出現設計要偵測的卡死與比例退化，不能證明所有輸出不可預測。例如 010101... 可以通過這兩項檢查，但完全可預測。獨立統計估計、物理來源模型與健康檢測需要一起使用，不能互相取代。

目前監測範圍為每通道二元失效；不宣稱它能偵測所有通道間鎖定、時脈注入、供電干擾或同步器亞穩態。啟動樣本的丟棄/資料可用定義已明確記錄，之後的 RO restart matrix 應取啟動檢查後的第一批可用樣本，不能混用舊版的時間點。
