# SHA3 成本與吞吐量測口徑查核

查核日期：2026-10-27。結論：文獻沒有統一到可以省略量測範圍的單一口徑。可以做 related-work 表，但本研究的主要定量結論應來自四版同 library、同 period、同合成政策、同 workload 的比較。

## 讀到的原文與本研究的決策

## 採用的三種數字

1. 主結果：full SHA3 功耗與 4096-byte 的端到端有效訊息吞吐。`TP_full = 32768/(C_e2e T)`。
2. 補充結果：另合成 standalone core，使用 `TP_core = 1088/(C_core T)` 與其自己的功耗。core 包括 scheduler、state bank、lane gating 與保護，排除 SHA3 外圍。
3. 舊法對照：`P_full/TP_core` 留在 CSV，名稱明示 core-normalized whole-engine estimate，不當成完整訊息實測能耗。

本機四版正常訊息皆為 C_e2e=7575、C_core=241，因此同 period 下從舊吞吐改成端到端吞吐，對四版完整 engine 的比值使用相同換算因子，不會單靠這個改動扭轉其同頻功耗排名。standalone core 是另一個合成邊界，其結果仍必須實際合成，不能由 full 數據推定。

## Related-work 表如何寫

建議欄位：文獻、年份、平台／製程、SHA3 模式、保護對象、方法、恢復能力、area 單位、power 方法與範圍、throughput bits／cycles 定義、原報數字、不可直接比較因素。

ArchHC 的 FPGA LUT/FF、Pessl 的 ASIC GE/RAM、以及本組 library cell area 應標原單位。不同製程、FPGA/ASIC、core/full、state bits/rate bits、post-layout/vectorless，不混成一張「勝過幾倍」排行榜。文獻表用來定位設計與取捨；四版共同比較才用來證明本研究的成本改善。

所有 power/throughput 比值均標明 vectorless power-normalized estimate。未使用同訊息的活動波形，不能把它稱為 measured transaction energy，也不能從正常功耗推算單次 replay 的真實能量。
