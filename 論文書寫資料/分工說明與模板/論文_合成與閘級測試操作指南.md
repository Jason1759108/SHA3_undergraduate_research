# 舊判定口徑＋default make vcs_gate（無 SDF 回標）（2026-10-28）

> **歷史診斷指南。** 此處的無 SDF 模式不是 2026-11-04 四版 03 結果；現行方法見 [工作站操作與資料說明](./工作站操作與資料說明.md)。

本說明取代先前以 CONSTRAINT_FAIL / NOT_VALID 作主判定的操作方式。

## 目前判定

- `SYN_OK`：合成完成，報告可讀，最大延遲分析 slack ≥ 0，沿用舊掃頻主要時間判定。不是所有電氣限制都通過。
- `SYN_TIMING_FAILED`：合成完成，但 slack < 0。仍執行該點 03，保留結果，繼續掃描其他週期。
- `AUDIT_ONLY`：transition、capacitance、額外時序涵蓋與結構檢查的報告。保留備查，不因這些報告內容阻擋流程。不調整或放寬實際合成約束。
- `TOOL_ERROR`：DC/VCS 執行、必要檔案、報告解析或環境有錯，停止該版本後續掃描。來源指紋與時間單位仍檢查，避免使用錯誤版本或錯算單位。
- `GATE_PASS`：正常輸入向量通過、工具正常結束、未偵測到模擬時間違反；不要求 SDF 日誌。不是故障注入覆蓋率，也不是完整實體驗證。
- `GATE_FAIL`：輸出不符、逾時、模擬失敗、時間違反。成功合成的其他週期仍會測試；編譯／環境錯誤則停止，避免連續重複失敗。
- `comparison_eligible=True`：SYN_OK 且 GATE_PASS；額外電氣限制不參與此欄。報告與論文須說明這是舊口徑。

所有產物與額外報告保留，不將「不作阻擋」改寫成「沒有違反」。未改 00_TESTBED、01_RTL，也未改本次之前的 Tcl 合成設定。

## 03 實際內容

每個成功合成的 full/core 點下建立自己的 `03_GATE/`，使用該點 netlist。將保存的原 Makefile 原封不動複製成 `03_GATE/Makefile`，直接執行 `make vcs_gate`，沿用原製程模型與 `+neg_tchk`，不新增 `+notimingchecks` 或其他關閉檢查選項。

不再呼叫 `$sdf_annotate`，不指定 MAXIMUM，也不要求 sdf.log。02 仍照舊輸出 SDF，Python 只讀取其中 DESIGN 名稱以連接正確模組，不把延遲載入模擬。結果標示 `gate_mode=default_make_vcs_gate_no_sdf`、`gate_sdf_annotation=NOT_REQUESTED`。

full 跑 18 組正常訊息，core 跑 4 組 1600-bit 向量。仍需按每個掃頻週期產生適用 SHA3 的測試平台與 filelist；固定刺激偏移縮放為週期十分之一，10 ns 時等於原來 1 ns。移除前版為 SDF 額外延後 core 載入檢查的動作。00/01 與 Tcl 不因本次變更修改。

此流程是原 make vcs_gate 選項下的正常功能模擬，不是 SDF 延遲回標驗證，也不是合成後故障注入。製程模型原有的時間檢查保留；若真的報出 Timing violation，仍會記錄並判定 gate 未完全通過。不能用這版的通過結果宣稱先前 SDF 模擬發現的問題已修復。

## 10 ns 舊數據

四版 full 10 ns 都輸出 `historical_comparison.json`，比較面積、動態／漏電／總功耗及 slack，列出歷史值、目前值、差值與舊紀錄精度下是否相符。

| 版本 | 歷史來源 | 解讀 |
|---|---|---|
| V0 | others/sweep_summary_C3.csv | 原始 C3 流程已由使用者確認重現。 |
| V1 | others/sweep_summary_1600.csv | 舊 1600 紀錄；不預先保證和目前保留保護單元的流程相同。 |
| V2 | others/sweep_summary_lane.csv | 舊 lane SECDED 紀錄；同上。 |
| V3 | others/make_ft_parity_vs_c3_report.py 的 PAR | 舊 parity 報告數據；不預先保證同流程。 |

`HISTORY_MATCH` 是所列五項數值在歷史精度下一致；`HISTORY_DIFFERENT` 會列差異，不會中止 03 或偷偷調參數來湊數。core 沒有這些完整 SHA3 的歷史對照，標 NOT_APPLICABLE。

先等舊工作結束，避免同時跑兩套。將最新 sha3_paper_complete.zip 上傳至 ~/sha3_paper_build。

```text
cd ~/sha3_paper_build
unzip -o sha3_paper_complete.zip 'V*/02_SYN/*' 'V*/03_GATE/README_PAPER.md' 'V*/prepared_hashes.csv' run_four_sweeps.sh run_dense_sweep.sh GATE_SWEEP_GUIDE.md
```

只更新指定檔案；不改 00/01、rtl_latest.json 或舊 results。程式在當次結果資料夾建立真正的 03，不覆寫學校 build 的原 03 腳本。

## 一次檢查四版 10 ns（建議背景執行）

```text
cd ~/sha3_paper_build
nohup bash run_four_sweeps.sh check < /dev/null >& check_launcher.log &
```

共四版 × full/core，各跑 02 後接 03，即 8 次合成及 8 次 gate 模擬。不要再次啟動同一批。查看：

```text
cat check_launcher.log
set logdir = `cat latest_sweep_logs.txt`
tail -n 30 "$logdir"/*.log
```

若 SYN_TIMING_FAILED 但 GATE_PASS，不代表時間分析被模擬推翻；該點仍不算已達成頻率。若 HISTORY_DIFFERENT，先檢查差異表。第一輪工作站檢查前，不能宣稱新 03 流程已成功執行。

## 正式掃頻

10 ns 的工具／編譯問題排除後，再啟動：

```text
nohup bash run_four_sweeps.sh dense < /dev/null >& dense_launcher.log &
```

10.0、9.9、…、1.0 ns，每版 full/core 共 182 點；四版最多 728 次合成與 728 次 gate 模擬，耗時會比原流程增加。timing/gate 失敗點不作最佳操作點，原始報告仍保存。不要先假設所有負 slack 點都會或都不會通過模擬。

## 保存位置

`V*/results/sweep/時間/full_10ns/`（core 同理）包含：

- `02_SYN/`：該點 Tcl、設定、DC log、Report、Netlist。
- `03_GATE/`：生成的測試平台、PATTERN 副本、filelist、原 Makefile、simv、gate.log、vcs.log、gate_summary.json。
- `historical_comparison.json`：full 10 ns 的歷史數字對照。

整批的 `sweep.csv` 新增 gate 結果與 comparison_eligible；`sweep_summary.json` 分開列工具錯誤、時間未達標與 gate 失敗。`operating_points.json` 中 `lowest_energy_old_criterion_and_gate` 才是本次口徑的最佳取樣點。`bash collect_results.sh` 會連同 03 結果全部打包。

若只想給舊的成功合成點補 03，而且該點還沒有 03_GATE，可在版本的 02_SYN 執行：

```text
python run_gate.py --point /完整路徑/results/sweep/時間/full_10ns --process TSMC40
```

此單獨補測只寫 gate_summary.json，不回寫舊 sweep.csv，避免改動舊實驗紀錄。
