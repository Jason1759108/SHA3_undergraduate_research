## 實際執行順序

run_sweep.sh → 舊 sweep_dc.sh 產生週期 → ./01_run_dc → make syn → 原 Makefile 的 setup_dc 與 dcnxt_shell → 原 Tcl → 舊 awk 解析/CSV → 保存該點產物 → make vcs_gate → 顯示與保存結果。

V1 的 01_run_dc 是 make syn SYN_TCL=syn_1600.tcl，必要原因是選取原本的 1600 Tcl；其餘三版與 test 範例一樣是 make syn。原核心數、工具旗標、library 由 Makefile 定義，不由 Python 重寫。run_sweep.sh 明確選 TSMC40，V3 明確選 FT_ENABLE=1。

sweep_dc_original.sh 是未修改的來源腳本；sweep_dc.sh 只新增兩段：每點結束後的保存/03/補充計算，以及整批結束後的摘要。週期、CLK_PERIOD、合成指令、原報告解析、舊 CSV 欄位和公式原封不動。

Python 2.7/3 只用於前置來源核對及合成後處理，不啟動 DC。run_sweep.py 與 paper_syn.tcl 等舊共同流程已退出新版。

## 指標與成功訊息

- 原 CSV sweep_summary.csv：舊 1088/(240×period) Gbps；整顆功耗除以這個理論吞吐量。用於重現舊數據，不冒稱整顆訊息實測能耗。
- supplementary.csv：完整 SHA3 的 T = 32768/(4096-byte 訊息實測 cycles × period_ns)，單位 Gbps。P 是整顆 SHA3 的 DC 總估計功耗（mW）；P/T 為 pJ/bit。測試以第一筆輸入接受到第八筆輸出被同步接收的週期間隔計算；不是大量訊息穩態流水線吞吐量。
- 功耗仍是原 DC 預設活動估計，不載入 PATTERN 波形。
- [HISTORY_ITEM]：10 ns 每項歷史值、現在值與 MATCH/DIFFERENT；[HISTORY_MATCH/DIFFERENT] 為整體比對。V0/V1/V2 比七項（含舊 T 與 P/T），V3 依其舊報告可取得的五項。
- [RESULT] status=OK/TIMING_FAILED/DC_FAILED/REPORT_MISSING/PARSE_FAILED：原腳本的合成判定原樣保留。OK 不代表所有電氣限制均通過。
- [GATE_PASS/FAIL/ERROR]：原 make vcs_gate 下正常訊息通過/失敗/環境或輸入檔案錯誤。無 SDF 回標，不關閉原模型時間檢查。
- [FULL_SHA3]：整顆的實測週期、T、估計 P/T。
- [POINT]：舊合成狀態、gate 狀態與是否可用比較。
- [SUMMARY]：完成點數、時間未達標、合成失敗、gate 失敗、可比較點數。HISTORY 不同另列，不冒充工具失敗，也不因比對不同而調設定。
- operating_points.json：最低整顆 P/T 的取樣點、符合舊時序判定且 gate 通過的最小取樣週期、負 slack 的最大取樣週期；不是連續頻率範圍的精確極限。
